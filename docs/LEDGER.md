# 炉次结算与用电排放证明

面向交付的两个页面：`/ledger`（炉次结算）与 `/ledger/certificates`（证明）。

## 为什么不是“先估再覆盖”

- 客户要的是**每炉**的产出、用电、排放证明，而车间只有跨炉次总表和晚到记录。
- 先按经验估会返工；等总表收齐会压住整批出货；总表补齐后直接覆盖又会与已交付证明冲突。
- 本工具把三者拆开：金额可以随晚到记录变化，但**每个数值都有结算版本**；证明**只追加**，旧版可查、可下载；只有验收完成的炉次才能出证。

## 业务流程

1. 导入台账（`/api/ledger/ingest`）。重复导入同一读数不会重复计入。
2. 页面 `/ledger` 按炉显示投料、产出、产出率、用电、排放、验收与结算状态。
   - 未结算：`未结算字段` 直接列出“投料 / 产出 / 用电 / 排放 / 验收”中缺哪项；
   - 原因：缺记录、区间重叠、同修订号冲突、验收未完成、验收早于返工等，均在 `reasons` 中说明。
3. 已结算炉次可出证；出证前先确认消耗的结算版本。
4. 晚到或修订资料再次导入后，结算版本号递增，页面“本炉为什么变化”给出变化说明；旧证明标为 `待换证`。
5. 重新出证后旧证明标为 `已替代` 并指向新证明；若炉次重新变为未结算，证明标为 `已失效`，行记录保留。

## 关键不变量

| 诉求 | 实现 | 位置 |
|---|---|---|
| 同一读数区间不重复计入 | 记录主键 (heat, record_key, revision, signature)，重导跳过；快照内同 key 只取一条 | `app/ledger/store.py`、`settle._pick` |
| 返工/复配重新结算 | 产出取整炉最高 revision，旧验收早于新产出判 `ACCEPTANCE_STALE` | `settle._acceptance_gate` |
| 只有验收完成可出证 | `issue()` 检查 `settled` 与验收结论 | `app/ledger/store.py` |
| 生成失败保留旧证据 | 事务回滚，不写证明行；失败记 `certificate_log` | `issue()` |
| 修订不覆盖 | 结算按 digest 追加版本；证明按 cert_version 追加并标记替代关系 | `run_settlement()`、`issue()` |

## 排放口径

排放 = 用电 kWh × 0.5703 kgCO2e/kWh（`EMISSION_FACTOR`），因子与版本写入证明与导出文件。证明封印为规则版本 + 规范化内容的 SHA256，可离线复核。
